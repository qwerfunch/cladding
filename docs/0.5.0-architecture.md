## The 2026 reality 0.5.0 builds on

When 0.4.0 shipped, only Claude Code had a mature native sub-agent surface. By the time PR-A was scoped, four hosts had landed equivalent surfaces (April 2026):

| Host | Sub-agent surface | Dispatch tool | Manifest format |
|---|---|---|---|
| **Claude Code** | Task tool (mature) | `Task()` | `plugin.json` `agents[]` + `.md` frontmatter |
| **Codex CLI** | Apr 2026 | `agent` + SubagentStart/Stop hooks | `.codex/agents/*.toml` |
| **Cursor IDE** | Agents Window + `/multitask` (3.0/3.2 Apr 2026) | `mode_switch` | `.cursor/modes.json` |
| **Gemini CLI** | Apr 2026 preview, **sunset 2026-06-18 → Antigravity** | `@agent` | `~/.gemini/agents/*.md` |
| **Antigravity** | Async background orchestration | `spawn_subagent` | dynamic |

This shifts the framing from "Claude Code first + others fallback" to **host-agnostic multi-agent first**. Cladding now ships a single canonical persona spec and transpiles to all four manifest formats.

## Single SSoT, 4-host transpile

```
src/agents/*.md   (canonical, 5 personas + hostHints frontmatter)
       │
       │   scripts/build-plugin.mjs · Phase E
       │
       ├──> plugins/claude-code/.claude-plugin/plugin.json · agents[]
       ├──> plugins/codex/agents/<id>.toml         (sandbox + MCP scoped)
       ├──> plugins/cursor/modes.json              (Custom Modes 2026)
       └──> plugins/gemini-cli/agents/<id>.md      (allowed_tools snake_case)
```

The transpile is idempotent. Run `npm run build:plugin` to regenerate. Phase D recounts detectors; Phase E recomputes each host's sub-agent manifest from the canonical persona spec. No manifest is hand-edited.

### Canonical persona spec — frontmatter

```yaml
---
name: librarian
description: SSoT custodian — keeps spec.yaml structurally clean.
tools: Read, Write, Edit, Bash              # Claude-style allowlist hint
capabilities: [read, write, edit, exec]      # provider-agnostic source-of-truth
# 0.4.10 PR-A.2 — per-host hints (all optional)
model: sonnet
permissionMode: acceptEdits
sandbox_mode: workspace-write
maxTurns: 12
---
```

`capabilities` is the SSoT for per-host capability translation (PR-B). `tools` is a legacy field used by hand-mirrored Claude Code manifests; capabilities-derived emission is a 0.5.x cleanup.

## Persona resolution + routing (PR-A.1)

`agents/routing.yaml` is the deterministic resolver: scope modules + intent tokens → persona. The host AI calls `enter_work({featureId, intent})` and cladding's `resolvePersona()` runs the rules in declared order. Explicit `personaId` always wins over routing. Fallback is `'specialists'`.

```
work request → resolvePersona({featureId, intent, scope})
              ↓
       agents/routing.yaml rules (first match)
              ↓ (fallback)
       spec.yaml::project.ai_hints.preferred_persona
              ↓ (fallback)
       'specialists'
```

The matched rule travels as `EnterWorkResult.routing.matchedRule` for audit trails.

## Dispatch flow (PR-A.3 + PR-B)

```
host AI: enter_work({featureId, intent})
        │
        ├─ detectHost(env) → {host, tier}
        ├─ resolvePersona() → personaId + routing.matchedRule
        ├─ loadPersona(personaId)
        ├─ translateCapabilities(persona, host) → CapabilityEnvelope
        ├─ defaultDispatchMode(tier) (sub-agent | host-self-inject)
        ├─ appendEvent('work_entered', {host, tier, dispatchMode, routing})
        │
        ↓
EnterWorkResult {
  personaPrompt,                     # for self-inject path
  subAgentDispatchHint {host, tool, subagent_type, advisory?},
  capabilityEnvelope {...host-shape},
  dispatchMode,
  routing {matchedRule, parallelGroup?},
}
        │
        ↓
host AI invokes its native dispatch tool with subagent_type=<persona>
+ tool allowlist / sandbox / model from capabilityEnvelope.
```

The host AI decides the action; cladding emits the contract. The auditor (PR-B `dispatchDrifts[]`) flags Tier 1/2 hosts that chose `host-self-inject` against the recommendation. Non-blocking — informational only.

## Parallel groups (PR-B)

`executeDrive()` returns a topological Kahn-levels grouping alongside the flat plan:

```
Scenario: A → B → C + independent D, E
plan:   [A, B, C, D, E]
groups: [[A, D, E], [B], [C]]
```

Hosts with native concurrent sub-agent dispatch fan out a group concurrently:

- Claude Code: multiple `Task()` calls in one response
- Codex: `agents.max_threads` (default 6)
- Cursor: `/multitask` async subagents
- Gemini: multiple `@agent` invocations

`ExecuteDriveResult.plan` (flat order) is kept for one minor cycle for backward compat. The `drive_started` event payload carries both `plan` and `groups`.

## Antigravity transition

Gemini CLI sub-agent support is preview, with a published sunset of **2026-06-18 → Antigravity**. cladding's transition policy:

- **0.5.0 (this release)** — Gemini CLI sub-agent wire stays. Antigravity has Tier 1 wiring in `detectHost`; manifest format is dynamic (no static file equivalent).
- **0.5.x** — Antigravity primary path documented + dogfooded.
- **0.6.0 (post-sunset)** — Gemini CLI sub-agent support marked deprecated; `dispatchHint.advisory` becomes a warn-level event.

User-facing guide: [`docs/migration/gemini-to-antigravity.md`](migration/gemini-to-antigravity.md).

## Four-layer defense (carried forward from 0.4.x)

A pure MCP-transaction model would depend 100% on the host AI calling `enter_work` before any Edit/Write. AI self-discipline is fragile. The 0.5.0 design keeps the four-layer defense from 0.4.x, now with sub-agent dispatch as the default Tier 1/2 substrate:

- **Layer A — AGENTS.md / CLAUDE.md trigger guidance.** Host AI reads the MUST-clause from project memory.
- **Layer B — MCP tool description compulsion.** Each tool's `description` field carries the same MUST-clause.
- **Layer C — host-specific PreToolUse hooks** (Claude Code today; Codex SubagentStart in PR-B follow-up). Strongest defense, limited reach.
- **Layer D — post-hoc unmapped-change scan + dispatch_drift detector.** `auditWorkCompliance` reports both file-diff drift and dispatch divergence.

Even with Layer C disabled, the A+B+D triad guards SSoT correctness.
