**Date:** 2026-06-10 ~ 06-11 · **Engine:** develop tarball (0.6.0-candidate, post-624825f)
**Method:** the 0.5.2 pattern, scaled up — tarball-install the engine like a real user

## 1. Deterministic battery — 31/31 PASS, 3 real bugs found and fixed

29/31 on first pass; the two FAILs were one root cause. All three findings were fixed,
re-packed, re-verified (commit 624825f):

| Finding | Class | Fix |
|---|---|---|
| `clad sync` test_ref repair ate 2 leading path chars under the REAL invocation (cwd='.'), persisted corrupt refs into user shards, re-fired on its own output every sync | SHIP BLOCKER — in-repo tests passed (absolute temp cwds); only the real-user path exposed it | `path.relative()` + no-op rewrite guard + `process.chdir` regression tests |
| Bare `npx tsc` on a toolchain-less machine auto-installed and EXECUTED the typosquat package `tsc@2.0.4` (not TypeScript) | Supply chain | all gate toolchain invocations are `npx --no-install`; absent tool → honest skip, escalated by the strict demand table |
| `clad serve` banner wrote to stdout — the MCP wire | Protocol corruption for strict JSON-RPC clients | banner → stderr |

Everything else passed as designed on the real install: verb aliases + deprecation
notices, `--with-hook` (both hooks), `--with-ci`, absolute-path setup rewiring,
sync repair/derived (post-fix), the full attestation loop (stamp → stale → re-attest),
the strict skip-policy demand table, all five hook protocol events (done-flip block
included), MCP `clad_run_gate` + `schema_version` + gate footer, identity-stamped
events with gate_run dedupe, 8-hex ids.

Headless probe (real Claude Code session): the PreToolUse hook **blocked a direct
done-flip instruction**, and the model responded by naming the sanctioned path
("run `clad done` to earn the flip") — structural enforcement holding against an
explicit user instruction to bypass it.

## 2. Hard-task 3-arm: event-sourced ledger (5 natural prompts, sealed oracle)

Same 5-prompt sequence (idempotent append → atomic transfers/overdraft → single-use
reversals with invariants → snapshot equivalence → wrap-up). Sealed 10-assertion
oracle, hidden from all agents. cladding oracle MANDATE off in all arms (0.6.0
default); the cladded arms VOLUNTARILY authored impl-blind oracles via
`clad_author_oracle`.

| | vanilla | cladding hooks-OFF | cladding hooks-ON (0.6.0) |
|---|---|---|---|
| sealed oracle, raw contract | 1/10 (`deposit` rejected) | 1/10 (same) | **10/10** |
| sealed oracle, vocabulary-adapted | **10/10** | 8/10 (2 real logic defects: replay rebuild, snapshot equivalence) | **10/10** |
| wall time | **11 min** | ~105 min† | 106 min |
| measured tokens (cost-proxy) | **$4.87** | $47.19† | $24.78 |
| turns | 62 | 418 | 360 |
| governance artifacts | none | 4 shards · 6 oracles · attestation 4/4 · 20 events | 4 shards · 4 oracles · attestation 4/4 · 14 events |
| done flow | n/a | 4 rejected → 4/4 earned | 2 rejected → 4/4 earned |

† hooks-OFF step 4 was killed externally (machine sleep + timeout) and resumed —
part of its cost is that contamination.

**Honest readings (n=1 per arm):**

1. **The conformance NULL replicates.** Vocabulary-adapted, vanilla ties the best
   cladded arm at 10/10. A capable model does not need cladding to be *correct* on
   a greenfield task — consistent with every prior A/B (6/9/34/48 features).
2. **The cladding premium on this task ≈ 5× tokens** ($4.87 → $24.78). Token
   attribution from transcripts: the voluntary oracle workflow consumed **~42%
   (ON) / ~52% (OFF) of output tokens** — agents went effectively exhaustive
   (one oracle per feature), exactly the pattern v8 measured as "+30% cost,
   ~0 quality on a capable model". The deferred risk-weighted default
   (`always_ears: [unwanted]` only) is the named lever to cut this; tool/persona
   guidance should steer the same way. **Classified as a design defect**: the
   oracle policy knob binds the GATE but not the BEHAVIOR — prose guidance
   overrode an undeclared (= no-mandate) policy and spent the user's tokens on
   verification the project never opted into. 0.6.1 fix: persona/tool guidance
   keyed to `clad oracle --required` (the policy's worklist), plus a
   "not mandated — voluntary" notice field on out-of-policy authoring calls.
3. **The 0.6.0 hooks halve the cost of being cladded**: ON vs OFF = −47% cost,
   −14% turns, 1.7× faster steps, and the only arm with zero adapted-logic
   defects. Structure injection paid for itself; the cache-write gap (0.98M vs
   6.06M) shows OFF churned context far more.
4. **What 5× buys is exactly the established positioning**: traceability
   (4 shards, ACs), the attestation stamp, impl-blind oracles, an
   identity-stamped audit ledger, and a process where 6 premature done attempts
   were rejected by the gate and then *earned* — zero bypasses. Not correctness.
5. Raw-contract divergence (`deposit` vs `credit`/`debit`) is an interface-
   interpretation coin-flip the prompt under-specified; scored both ways above.

## 4. Verdict

- 0.6.0's structural machinery works under real usage: install lanes, hooks
  (including against explicit bypass instructions), attestation, demand table,
  repair, MCP channel, events.
- The battery paid for itself before any LLM spend: one data-corrupting ship
  blocker + one supply-chain exec would have shipped without it.
- Sell sheet stays honest: governance costs real tokens (≈5× on a greenfield

  planned cost lever), buys traceability and enforcement — not correctness.
  If you run cladding, run it hooks-on: same price class as prose-mode at half
  the tokens, with the bypasses structurally closed.

**Honest readings:** 0.5.2's 48 minutes were SUBPROCESS time, not tokens (25
messages — its gates re-ran tsc/vitest repeatedly in a heavy fixture); 0.6.0's
$7.79 came from the Stop hook BLOCKING session end twice and forcing repair
loops (213 messages) — governance pushed to completion, at token cost. This
REVERSES the simple-task cost ordering: single-run deltas are high-variance;
treat per-task numbers as directional only.

**Finding (fixed in ea6c804):** the 0.6.0 agent created all three shards as
`status: 'done'` through `clad_create_feature` — zero `done_attempted` events,
no earn ritual, and the hand-flip hook never fires on an MCP call. A clean
bypass of the earn invariant. Creation now downgrades a requested 'done' to
in_progress with a note naming `clad done`. This is the second release-blocking
class these external campaigns caught that the in-repo suites missed.

Second mid-scale task, different domain (dependency recalc → range functions →

| | vanilla | 0.5.2 (released) | 0.6.0 (b52702c) |
|---|---|---|---|
| sealed oracle | 12/12 | 12/12 | 12/12 — full tie (eighth conformance NULL) |
| wall | **6.4 min** | 21.6 min | 16.6 min |

| messages | 36 | 128 | 143 |
| governance | — | 3/3 done, all gate-earned | 3/3 done, all gate-earned — but see the skew finding |

**Readings:**

- **Premium 3.3–3.7× vs vanilla**, inside the predicted 3–4× band. 0.6.0 was
  cheaper (−10%) AND faster (−23%) than 0.5.2 — directionally consistent with
  §5's −47%, smaller magnitude. No Stop-hook runaway this time: one
  `stop_blocked` (step 2), resolved in-session; the §6 repair-loop blowup did
  not recur on the rebuilt engine.
- **The earn ritual worked end-to-end on both cladded arms**: the 0.6.0 arm's
  first `clad done` was REJECTED by a RED gate, the agent repaired, then earned
  all three flips GREEN; zero hand-flips, zero done-at-creation attempts (the
  §6 bypass class did not reappear).

**Finding (open, version-skew):** the 0.6.0 agent typed `npx clad done` —
and npx resolves npm packages, not the runner's PATH-pinned engine, so the
flip ran the machine's STALE global cladding@0.5.0 while the same session's
MCP tools ran the bundled 0.6.0. Consequence: done flips were still
gate-earned, but on the old engine — no `done_attempted` ledger events, no
attestation stamp; 0.6.0's observability layer was silently bypassed. The
0.5.2 arm dodged it by typing bare `clad done` (PATH-resolved correctly).
This is the real upgrade topology (new plugin + stale global) — lever for
0.7: a `clad_done` MCP tool so the flip stays on the bundled engine, and/or
`clad done` printing its engine version so skew is visible in-session.
